# 设备同卦扫码联调

状态：2026-10-31。此前 0.3.0 固件与 GitHub Pages 静态同卦扫码已由使用者验收；本轮新增 Mac 中转驱动的认证扫码签文，用户确认第 14 卦「大有」出纸正常、手机内容一致。下文保留此前演示发布的历史证据；本轮服务、启动方式与完整验收范围见 [WEB_LOCAL_SETUP.md](WEB_LOCAL_SETUP.md)。

## 本轮认证扫码增补

无需重新烧录。中转为每个新事件创建 reading_id 和一次性 token，把 `qrurl <临时HTTPS基地址>/r/<token>/` 写入设备；收到 `QR_URL_SAVED` 后才生成固定短签并打印。手机领取后展示同一份短签，再生成网页长解读、主题和问答。固件仍按原时序显示 QR，不表示已取得打印完成反馈。

当前 [临时服务](https://lighter-windsor-eventually-clips.trycloudflare.com) 于 2026-11-01 11:34 恢复，已通过公网健康与资源检查。此前真实长解读、事业主题、问答、刷新和日历回看已由主控验证；本次更换隧道未重新执行全部 AI 交互。64 卦新 URL 编码均至少 3 px/module，但不代表每卦手机或真实模型均已测。隧道曾断连约一分钟后自动恢复，仍是临时联调方案。

token 创建后 10 分钟内仅一个浏览器可领取；新签撤销旧未领取 token。Cookie 会话有效 30 分钟，已保存本机历史可继续只读回看，过期后不能续问。临时域名和旧 Pages 的历史隔离；旧 `#d=` 参数仍是公开演示标识，不能授权访问真实签文。先启动临时服务、确认公网地址配置，再启动打印中转，勿同时占用串口。

## 此前静态演示行为

1. 待机 Logo 和已验收的摇动检测保持不变。
2. 揭示上卦、下卦，双卦同屏 6 秒后显示二维码；轻触切换回看，长按回首页，再摇生成新事件。
3. 配置为空时显示“网页待上线”。可通过串口 `qrurl <HTTPS 基地址>` 写入 NVS，无需为后续更换地址重新编译；配置更新会更新当前演示链接。
4. 二维码格式：`<base>#d=<1..64>.<16位小写十六进制启动号>.<1..4294967295事件计数>`。启动号由两个随机值组成，计数回绕会更新启动号。每次起卦仅选一次卦象，翻页不会重新选卦。
5. H5 从共享 64 卦数据映射上下卦；首次打开保存本机历史，重扫保持原记录与首次日期。相同记录号但不同卦象、越界或格式错误显示无效入口，不新增历史。
6. 设备记录标记 device_demo，仅展示卦象和联调说明。没有真实纸签、AI、主题深解、问答或领取认证；该入口禁用主题/问答，防止给随机卦套用固定乾卦内容。无设备参数时仍可使用既有编辑演示。

启动号是公开去重标识，不是秘密 token。正式后台必须另外实现设备认证、幂等事件、不可变签文、认证领取与有效期。
