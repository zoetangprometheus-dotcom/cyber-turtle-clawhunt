# Mac 电脑打印中转

日期：2026-10-31。无需 USB Host 模块，复用已验证的 PyUSB 打印通道与现有 0.3.0 固件串口事件；不重新烧录，保留 Logo、摇动阈值与双卦时长。本轮通过既有 qrurl 命令把每次新签的二维码更新为认证领取入口，详见 [本机扫码服务](WEB_LOCAL_SETUP.md)。

已加入 [本机 AI 配置窗口](AI_LOCAL_SETUP.md)，DeepSeek Flash 真实调用通过；用户确认大有卦纸签出纸正常、手机内容一致。下文「演示票」仅指未启用 AI 的旧路径。串口读取与生成/打印分开执行，过时结果不打印，生成失败不自动改印演示票。

## 连接和使用

1. ESP32 USB-C → Mac；打印机 USB-B → Mac，可通过现有扩展坞。
2. 打印机使用原配 12V / 2.6A 电源，开关拨到 I 并装纸。GPIO 彩线不用连接打印机。
3. 新扫码链路先双击 `启动临时扫码服务.command`，确认服务健康及公网地址写入，再启动 `启动电脑打印中转.command`。看到 READY 后保留终端窗口。程序只处理启动后新产生的事件，不补印此前屏幕停留的卦。
4. 摇动设备，进入双卦同屏时创建本次 reading_id 和 token、发送 qrurl，收到 `QR_URL_SAVED` 后才生成短签并打印。更新失败/超时不生成或打印。屏幕仍按原定时间显示二维码，纸签不印二维码。
5. 双击 `停止电脑打印中转.command`，或在前台终端按 Ctrl+C 停止。重新烧录或使用其他串口工具前先停止中转。

Mac 必须保持开机、唤醒，两台设备保持连接。没有安装开机自启动服务。若拔线、USB 写入失败或程序报错退出，检查接线和出纸情况后重新启动；旧事件不会自动重印，重新摇动会产生新卦。不能把重新摇动称为重试原签。

未启用 AI 的旧演示票只显示卦象，不套用固定乾卦签文；启用 AI 后使用已固定的 title/message/action，并标注 AI 来源。网页读取同一份短签再延展长文。领取有效期、会话、历史与失败重试按 [WEB_LOCAL_SETUP.md](WEB_LOCAL_SETUP.md) 执行。

## 命令与依赖

依赖已安装在本项目 `.local/esp32/python`：pyserial、pyusb、libusb-package；无需全局驱动或修改系统默认打印机。其他协作者需先准备 Python 环境并安装依赖，参见 PRINTER_XP58IIH.md。

```sh
# 默认只模拟，不出纸
.local/esp32/python/bin/python scripts/print-bridge.py
# 开始监听并实际打印
.local/esp32/python/bin/python -u scripts/print-bridge.py --send
# 停止本项目的中转进程
.local/esp32/python/bin/python scripts/print-bridge.py --stop
# 定向测试，不访问硬件
python3 tests/print-bridge.test.py
```

串口默认仅在 CH343 设备唯一时自动选择；多设备时显式传 `--port`。`--trigger-once` 用串口启动一次真实起卦，仅供联调，正常启动不使用。重复启动会被项目锁阻止。

## 去重和错误边界

- 串口 EVENT 的编号、上下卦和六爻必须与 data/hexagrams.json 一致；仅在随后 STATE 3 时发送。回到首页或设备重启会清除待打印事件。
- `.local/esp32/print-bridge.sqlite3` 在写入 USB **之前**持久记录事件；同一事件切换页面、重复输入或程序重启均不自动重印。不要为了恢复打印而删除数据库。
- `usb_sent` 只代表 USB 已接受全部数据，不代表已检测到出纸。失败记为 `uncertain` 并停止，不自动重试可能已部分输出的票据；中途退出留下 `attempting` 也不会自动重印。缺纸、过热等可靠状态反馈仍待验证。
- 复用固件现有 `bringup-32位启动随机号-事件计数` 作为本地事件去重键；网页 Store 为新事件另建 reading_id 和一次性 token。设备事件编号不是认证凭据，重复事件不会重新发 QR 或改写短签。
- 当前固件并不等待电脑打印完成后才显示 QR，仍按原时序进入 QR。不能宣称已具备正式「确认打印完成后领取」闭环。
