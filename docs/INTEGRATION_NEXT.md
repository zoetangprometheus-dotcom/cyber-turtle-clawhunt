# 下一轮整机与 AI 接入

日期：2026-10-31。本轮已用 Mac HTTP/SQLite 服务与 Cloudflare 临时 HTTPS 接通扫码签文，作为当前整机联调实现；启动与现行契约见 [WEB_LOCAL_SETUP.md](WEB_LOCAL_SETUP.md) 和 [BACKEND_AGENT.md](BACKEND_AGENT.md)。本页保留后续与队友正式后端的对接清单，迁移时确认兼容与归属，不把临时服务视为生产托管完成。

## 当前实测状态

| 链路 | 当前结果 | 下一步依赖 |
|---|---|---|
| Logo、摇动、随机双卦 | 使用者已确认 | 保留现有固件表现 |

| 本机历史与日历 | reading_id 保存、刷新/日历回看通过，独立历史入口零 API 请求 | 真实会话过期与更多手机验证 |

## 后续迁移时请正式后端提供的最小资料

1. 测试 HTTPS 地址、接口文档或代码分支；每个接口标注已实现/未实现。
2. 设备创建事件：设备鉴权如何配置、幂等事件标识、卦象输入格式；返回稳定 reading_id、基础签、网页长解读、二维码入口和有效期。
3. 浏览器领取/恢复：具体请求方式、Cookie/会话、过期/已领取/无权限/失败状态。当前公开 #d= 演示参数不能作为真实访问授权。
4. 主题和问答：请求体、任务状态/轮询路径、结果字段、错误码及重试方式。每次响应必须能核对 reading_id、theme 或 question_id。
5. 至少一组脱敏成功响应及错误响应。不要通过聊天或公开仓库发送模型 Key、设备密钥、token 或真实问答。

现有内容字段、主题枚举、不可变记录规则见 [BACKEND_AGENT.md](BACKEND_AGENT.md)，字数/提示词见 [AI_CONTENT.md](AI_CONTENT.md)，输出约束见 schemas/ai-output-schemas.json。当前 H5 使用已实现的同源 API；迁移前不把未确认路径、模型或鉴权写入已运行入口。

## 建议联调顺序

1. 后端锁定一条 reading_id 和同一卦象，生成基础短签及网页长解读；先用现有电脑 USB 脚本验证短签编码，不将它称为最终无电脑链路。
2. H5 领取/恢复这条记录，展示真实来源；请求失败不回退伪装成 AI 成功，也不把默认乾卦套给随机卦。
3. 接四主题与同卦问答；锁定基础签，重试不重抽卦、不重复打印，切签后忽略迟到响应。
4. 接 USB Host 后由 ESP32 发同一张纸签；落实打印故障/重试，成功条件明确后再展示正式领取 QR。
5. 完整验收：纸短网页长、纸签/屏幕/网页同一卦、重扫去重、日历回看、断网恢复、缺纸与断线不重复打印。

现有 64 卦的 meaning_modern 仍为 null，review_status 为文化未审核；不能称为已审核知识库。由团队确定可用知识材料并审核，AI 不应编造古籍引文或动爻/变卦。

GitHub Pages 仍仅托管此前静态演示，不能保管 Key 或运行模型服务。当前临时服务使用 H5/API 同源、HttpOnly Cookie、Origin/Host 校验且不开放 CORS；token 有效 10 分钟，会话 30 分钟。临时域名曾断连约一分钟后恢复，不承诺生产可用性。不同域名的历史不能自动迁移，稳定域名与迁移方案需另行确认。
