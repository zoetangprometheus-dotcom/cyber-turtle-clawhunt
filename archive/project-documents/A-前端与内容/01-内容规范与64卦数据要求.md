## 固定原则
- 先基础今日签，扫码后主动选择今日/自我、感情、事业/学业、友情。
- 卦象、卦名、六爻和基础签是同一记录的固定快照。模型不得重新起卦或生成名称/爻线。
- 内容温暖、具体、略有幽默，不宣称预测准确；不推断用户已有伴侣、就业状况、性别或正在遭遇某事。
- 用户可保存基础签，不必请求深解；不增加出生资料；增加可选问卦输入，沿用当前卦象。

## 字数规范 v0.1（提案）
以 Unicode 字符计数，包含标点，不包含排版换行。实际打印测试后再调整；不是已确认的物理容量。
| 阶段 | 字段 | 字符数 | 用途 |
|---|---|---|---|
| 基础 | title | 4–12 | 一眼能记住的标题 |
| 基础 | message | 20–50 | 一个明确启发，避免连续抽象形容词 |
| 基础 | action | 8–25 | 一个今天可以尝试的小动作 |
| 深解 | title | 4–16 | 与所选主题对应 |
| 深解 | meaning | 80–400 | 已核对卦意的现代解释 |
| 深解 | reflection | 80–400 | 对主题的开放启发，不断言现实 |
| 深解 | action | 12–100 | 可执行的小行动 |

短标题、按钮可以不加句末标点。正文正常断句；不为了“古风”牺牲理解，不强塞古语、吉凶分数或幸运数字。

## 文案编辑口径
| 避免 | 改写方向 |
|---|---|
| 你的正缘马上出现 | 把注意力放回相处是否舒服，也给表达留一点空间 |
| 今天一定升职加薪 | 先让一件具体工作更清楚，看看下一步需要什么支持 |
| 宇宙正在给你信号 | 把这张签当作一个暂停和观察的机会 |
| 一切都会好起来 | 指出一个用户可以观察或行动的具体角度 |

这些是创作示例，不是古籍译文。医疗、投资等内容不生成结论性指令；不以卦象替用户判断他人是否忠诚、疾病或损失。

## 64 卦字典的数据提案
每条记录需要：
- `hexagram_id`：建议采用文王卦序 1–64，待 A/B 共同锁定。
- `name_zh`、`upper_trigram`、`lower_trigram`：来自经核对的字典，不由模型填写。
- `lines_bottom_to_top`：6 位 0/1；0 阴、1 阳；索引 0 是最下爻。数组前 3 位为下卦，后 3 位为上卦。画在屏幕上时从数组末项向前排列。
- `keywords`、`meaning_modern`：A 编写的现代解释，与原文分开。
- `source_url`、`source_locator`、`source_checked_at`：逐条记录实际阅读过的来源及章节。
- `review_status`：`unverified / reviewed`；只有完成核对才改成 reviewed。

本提案暂不涉及动爻、变卦、互卦，避免引入 v3.1 未要求的系统。

## 核对顺序与验收
1. 选定可以追溯的中文版本；保留版本名称和章节位置。
2. 建立八卦固定编码，再核对 64 个上下卦组合与文王卦序映射。
3. 用不同来源复核名称和图形；现代解释由 A 审稿，不能把开源 AI 翻译当古籍权威。
4. 自动检查 ID 1–64 完整且无重复，8×8 组合完整，六爻长度/取值正确，上下卦和拼接结果一致。
5. 另做人工文化核对。自动检查通过只证明结构一致，不能证明来源和解释正确。
6. 用至少一个非对称卦做屏幕/纸签上下方向测试，纯阳或纯阴无法暴露倒序问题。

当前没有完成 64/64 核验。02 和 07 使用乾卦作为编辑样例，`meaning` 属于现代创作；样例不能用作方向测试或全库正确性的证据。
