## 已确认的问题（后续三项均已修复，原始发现保留）
### F01 / P1 / 已解决：多页面保存同一签可能丢失问答
- 定位：h5/history.js:8，save 删除旧记录再放入调用方传入的整个快照；app.js:11 的 persist 不合并已有问答。
- 证据：使用真实 history.js 和内存 Storage 复现：A/B 同时读取一份记录；A 添加问题 A 保存，B 在旧快照添加问题 B 保存。最终读取 questions 只有 B，A 被覆盖。是代码级可复现结果，未伪称两个浏览器真机测试。
- 影响：手机重复扫描打开多个页签，或旧页签恢复操作，可能覆盖另一页新保存的解读/问答。
- 修复方向：以 reading_id 归组，按 question_id 合并问答、按主题合并成功结果，纸签快照保持不变；同时监听 storage 事件或刷新最新记录。跨标签同时写入还需序列化写入或事务存储方案，不能只靠一次读取后合并宣称彻底解决竞态。
- 验收：两个页面交错添加不同问题，刷新后两个问题都存在，旧纸签不被回写覆盖。

### F02 / P2 / 已解决：历史内容校验不完整，局部坏数据可能让页面初始化失败
- 定位：h5/history.js:6 与 app.js:14、17。
- 证据：真实 valid() 接受 questions:[{}]；renderQuestions 随后传入 undefined answer，appendSections 访问 content[key] 会抛错。源码与 validator 执行证明，未向用户浏览器写入坏数据。
- 影响：已有数据发生局部损坏/字段迁移不兼容时，顶层 JSON 合法但无法显示页面，现有读取失败提示不会兜住此情形。
- 修复方向：增加版本化的嵌套字段校验，隔离有问题的记录并保留原数据，页面仍可打开；不要直接清空整个历史。
- 验收：缺 answer、坏日期、错爻线等输入分别得到可理解提示；完整旧记录仍可回看。

### F03 / P2 / 已解决：日历选中日期后键盘焦点丢失
- 定位：h5/app.js:35，点击后 renderCalendar 重建所有日期按钮。
- 证据：浏览器点击第一天后，document.activeElement 为 BODY，ID 为空；原按钮被 replaceChildren 移除。
- 影响：键盘用户连续选日期需重新导航，焦点位置与视觉选择脱节。
- 修复方向：保留现有日期按钮或在更新后把焦点恢复到同一日期；月份切换保留合理焦点。
- 验收：使用 Tab/Enter 选择日期后焦点仍在选中日期，继续操作不回到页面开头。
