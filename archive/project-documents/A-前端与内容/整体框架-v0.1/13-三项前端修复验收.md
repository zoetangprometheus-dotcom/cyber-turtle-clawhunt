# 三项前端修复验收

## 给后续 Codex
用户要求修复 12-前端剩余工作审查中的 F01/F02/F03。本次只修改 h5/history.js、h5/app.js 和相应测试/交接资料；纸签比例、视觉、文案、真实 AI 接入范围不变。

## 已解决
| 问题 | 修复 | 验证 |
|---|---|---|
| F01 同一签多页面保存覆盖问答 | Web Locks 同源排他锁串行化读/合并/写；按 question_id 合并问答、按主题保留成功结果；原纸签和网页快照不覆盖；新问题用独立随机 ID；监听 storage 事件更新其他页面 | 模块测试中两份旧快照并发保存，两个问题和两个主题均保留。浏览器两页分别提交 A2/B2，提交完成后刷新两页，都看到原问题及 A2/B2 |
| F02 局部历史坏数据导致页面出错 | 校验日期、六爻值、基础/网页内容、主题对象、问答 answer 等嵌套字段；隔离不完整/重复 ID 记录至 quarantined，保留原对象；正常记录照常使用；无法解析顶层 JSON 时不覆盖原数据 | 七类坏对象校验失败；正常记录保留；保存后隔离原对象不丢、不重复。浏览器追加 questions:[{}] 测试记录，页面正常显示其他三条问答并出现保留提示 |
| F03 日历选择后焦点丢失 | 日期按钮加入 data-day；重绘后恢复选中日期的焦点；其他标签触发历史刷新时也保留日历焦点 | 点击 10 月 1 日后 activeElement 为对应 BUTTON；Tab 到 10 月 2 日，Enter 后仍聚焦第 2 日，aria-pressed=true |

## 兼容与边界
本轮继续使用现有 localStorage，没有新增依赖。浏览器不支持 Web Locks 或无法取得锁时，不退回有竞争风险的裸写入，显示未保存提示，已有可读记录仍可看。建议在稳定 HTTPS 页面或本机 HTTP 预览使用；直接 file:// 的行为仍取决于浏览器。所有已打开旧页面需刷新才能使用新的写入协议，旧版脚本不受新锁约束。

机制依据：[MDN Web Locks API](https://developer.mozilla.org/en-US/docs/Web/API/Web_Locks_API) 和 [LockManager.request](https://developer.mozilla.org/en-US/docs/Web/API/LockManager/request)，2026-10-31 查阅；同源多个页面请求同名排他锁时会排队。本轮已在当前浏览器验证，不宣称覆盖所有手机浏览器版本。

隔离原对象是保留证据，不是自动修复其内容；仍未添加历史恢复编辑 UI。真实扫码、模型调用、硬件打印及手机相册验证继续按原待办推进。
